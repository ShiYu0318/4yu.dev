# mAIjong 麥醬

> [!SUMMARY]
> 一個台灣十六張麻將的完整平台：可以和朋友開桌、跟不同難度的 AI 對戰、讓 AI 教練分析每一手；同一套規則引擎也是強化學習的訓練環境，研究者能訓練、重播、比較自己的代理程式。

## 為什麼做這個

麻將 AI 的研究大多集中在日本麻將，台灣十六張的規則（十六張手牌、花牌、台數計分）幾乎沒有開源、可重現的研究環境。我想要一個「**玩家玩得到、研究者訓練得了**」的平台：遊戲裡的每一局都由同一個規則引擎判定，訓練出來的代理也能直接上桌和真人對打。

這個專案從 Java 課程的期末專題起步，後來整個改寫成現代全端架構。

## 核心功能

- **線上對局**：快速配對或開私人房間、分享房間碼，空位由 AI 補上；斷線時電腦暫代，回來後接手。
- **五級 AI 對手**：Lv1 隨機、Lv2–3 規則代理、Lv4 可載入 DQN、Lv5 讀取經過晉升評估的最佳代理。
- **AI 教練**：局內顯示向聽、有效進張、聽牌與危險牌；提供課程、手牌分析與決策問答。
- **複盤與練習**：錄影與註解、情境練習、速度挑戰、防守練習，以及排行與賽季。
- **研究實驗室**：在固定牌譜上做模擬、策略比較、訓練任務與指標追蹤。
- **Agent SDK**：對外開放的 `maijong-sdk`，讓任何人寫自己的代理並提交到社群競技場。

## 技術架構

| 層級 | 技術 |
|---|---|
| 前端 | Next.js 15、React 19、PixiJS 8、Zustand、Tailwind CSS 4 |
| 後端 | FastAPI、WebSocket、SQLAlchemy / Alembic |
| AI / 模型 | PyTorch、Gymnasium、PettingZoo、PPO / DQN、CEM 調參 |
| 資料 | SQLite / PostgreSQL，選用 Redis、S3 相容儲存、Celery |
| 測試 / CI | 引擎、AI、後端、SDK 與端對端測試，GitHub Actions |

瀏覽器透過 HTTP API 處理帳號、建房與練習，透過 WebSocket 同步牌局。**後端持有權威局面**：前端送出的每個動作都由純 Python 規則引擎驗證，傳給玩家的局面會遮蔽其他人的暗牌。AI 代理與訓練環境共用同一個引擎與特徵編碼。

## 技術亮點

### 零依賴的規則引擎

`engine/` 是零執行期依賴的台灣十六張規則實作：`GameState` 管一手牌的手牌、副露、牌河、牌牆與行動階段，`Match` 管跨手的局數與莊家推進，`get_legal_actions` 決定每個座位能做什麼。計分先選胡牌拆解與台型，再依支付者與莊家關係結算。

> [!HIGHLIGHT] 同一個引擎，三種用途
> 遊戲後端、RL 訓練環境、對外 SDK 都呼叫同一個引擎，所以「訓練時學到的規則」和「上桌時判定的規則」永遠一致。

### 強化學習問題定義

| 項目 | 設計 |
|---|---|
| Observation | 34 種牌 × 14 通道（手牌、副露、各家牌河、有效進張、風位…）+ 13 個局面數值 |
| Action | `Discrete(108)`，涵蓋打牌與吃碰槓聽胡 |
| 合法性 | `legal_mask`，只在可行動作中選擇 |
| Reward | `potential` preset：以牌型品質的前後差與實際支付點數為主 |

用「前後差」而不是「有進步就給分」，是為了避免策略學會反覆拆牌再重組來刷獎勵。另外也提供四席都可由代理控制的 PettingZoo 多代理環境。

### 公平的模型評估

新模型要「晉升」為遊戲裡的 AI，必須在**同牌譜配對評估**中勝出：相同的牌山、輪替座位，消除運氣造成的變異。

### 即時連線的效能

WebSocket 支援批次訊息，同一波事件只保留最後一份完整狀態；前端 PixiJS 用 sprite pool 重用牌張物件，DOM 層負責操作鈕與無障礙內容。
