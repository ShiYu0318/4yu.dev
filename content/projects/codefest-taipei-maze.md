# 北車不迷路

> [!SUMMARY]
> CodeFest 2026 的團隊作品：在台北通 App 裡找設施、選路線，用看得懂的步驟穿過台北車站。我們把搜尋、最近可達路線、QR 重新定位、圖像指引與集合點分享接成一條連續流程，讓人每次只需要確認下一步。

## 為什麼做這個

台北車站的尋路問題很具體：想去廁所，卻不知道哪一間真的走得到；知道目的地，卻不確定在哪裡換樓層；跟朋友約好，卻說不清楚集合點。地圖上「最近」的設施可能隔著牆，讀圖與跨樓層又要反覆切換畫面。

我們想做的是一個**每次都告訴你下一步能做什麼**的導引，並且直接嵌進台北市民已經在用的台北通。

## 核心功能

- **找最近可達設施**：依可通行路徑而不是直線距離搜尋，選好類別按「帶我去」就出發。
- **無障礙路線**：先排除樓梯、電扶梯與可及性不明的路段再求解；找不到就說明原因，不偷偷放寬條件。
- **同頁導航**：地圖、大方向圖示、沿途地標、樓層切換與上一步 / 下一步集中在同一個畫面。
- **QR 重新定位**：迷路時呼叫台北通原生掃碼確認位置，保留目的地並重新計算。
- **七語與閱讀偏好**：繁中、英、越、印尼、泰、韓、日，另有兒童 / 長輩模式、注音與大字。

## 技術架構

| 層級 | 技術 |
|---|---|
| 前端 | Vue 3、Vue Router、SVG 圖面與路線 |
| 資料 | 版本化 JSON（點位、跨層連線、步行圖）、七語訊息檔、注音詞庫 |
| 基礎設施 | 台北通 TownPass（Flutter）WebView 橋接、Docker 多階段建置、nginx |
| 測試 / CI | Node.js test runner、Vue SFC renderer 測試、ESLint、Python `unittest`、GitHub Actions |

服務以台北通的 WebView 微服務形式運作，搜尋與路徑計算都在本地完成；需要掃碼時才透過 `flutterObject` JSON 橋接呼叫原生功能。

## 技術亮點

### 從圖面產生可通行的路網

步行圖產生器讀取各樓層的可行走多邊形，放入設施與牆角轉折點，檢查每一條線段是否真的在走道內，再依設備資料加入跨樓層連線。展開後是 **519 個節點、4458 條有向邊** 的稀疏圖，用 Dijkstra 求最短的圖面成本路徑。

> [!HIGHLIGHT] 無障礙是「排除」，不是「加懲罰」
> 需要無障礙時，樓梯、電扶梯與可及性不明確的邊會在求路前直接移除，而不是只給一個很大的成本。這樣系統就不會在「其他路很遠」時仍然選中樓梯。

### 容錯的多語搜尋

查詢先做 Unicode 正規化，再比對本地詞典、同義詞與意圖，並用 Optimal String Alignment 容忍有限的錯字，讓使用者打錯字或用不同語言也找得到設施。

### 我負責的部分

這個 repo 共 350 個 commit，其中 228 個是我寫的。另外，我在台北通的 fork 中做了宿主端整合：持續掃描的 QR 定位與即時導引、在手機上執行的本地 Gemma 對話與語音，以及原生動作和畫面上的導引步驟同步。
